## Policy and checkpoint invariants

- Preset names use `base_variant__modifier`: architecture names retain single underscores (`mat_qcx`, `tmasac_dec`); modifiers use double underscores (`mat_qcx__lstm`, `masac__deepset_critic`). Removed names have no aliases. Registry membership comes from `variants.py`; retained low-level builders are not necessarily public presets. Actor/critic encoder sharing differs from sharing between Q heads.
- Model scales are fixed, versioned, task-independent declarations, never runtime fitting. Names are `2.5M`, `5M-2L`/`5M-3L`, `10M-3L`/`10M-4L`/`10M-5L` with their NOP suffixes; fresh-run layouts remain `v1` without migrations. Depth labels count actual actor and critic encoder blocks; `ScaleLayout.actor_encoder_layers` derives from `layers`. Action head/decoder depth is separate and fixed at one block. Encoder widths vary across depth choices to preserve actor FF/attention ≈2:1 and critic FF/communication ≈1:1, but remain identical across methods within each layout, including decentralized and off-policy actors. Action-head widths compensate for narrower encoder streams to retain comparable non-attention budgets. Registry order is budget then depth and controls gallery order. `ScaleLayout.slug` separates equal-budget depths; `model_scale=None` / CLI `custom` enables explicit-width builders. Plain PPO retains its shared flattened backbone.
- MAT owns independent actor/critic encoders: `encoder_config` is actor, `critic_encoder_config` critic. RMAT state maps `actor`/`critic` histories; rollout advances both, inference actor only, bootstrap critic only. MAT/RMAT NOP consumes the attached critic-encoder output from the same evaluation pass; use `nop_latent_dim` for its source width. Recurrent NOP follows critic history, not actor history. Compiled joint evaluation may materialize zero gradients for unused outputs; isolation tests check zero gradients and unchanged weights. Recurrent MAT adds memory to the unchanged feed-forward backbone. Fixed recurrent TMASAC also preserves the full feed-forward encoder/decoder, disables inter-module FF splitting, and adds temporal capacity. Custom-width builders retain the configurable split. State adapters use actual memory width; fixed dense LSTM/headwise sLSTM widths match complete main counts.
- MAT/RMAT critic observation inputs include privileged local/global fields before embedding, attention and recurrence; value heads consume only encoded features. `mat/independent_encoders.py` owns input assembly for rollout, sequence training and critic-side NOP. Fixed critic dimensions use the same scale builder as off-policy critics, with a separate `critic_temporal_hidden_dim` for recurrent MAT. Actors remain public-only.
- Fixed token-based actors receive about 40% of the base main budget, with 80–90% in their observation encoder. `_actor_encoder` shares width/depth/FF across MAT/MAPPO/off-policy methods; local actors replace each attention with a `D -> 2D -> D` residual MLP. IND/DEC/MAPPO and independent off-policy heads share one generic pre-norm residual block plus final LayerNorm in `nn_components/residual_mlp.py`; fixed output projections are identities. QCX/Original MAT retain the identical encoder, match the non-attention head budget including all adapters/readouts, and add decoder attention above that budget. `parameter_counts.processing.actor_decoder_attention_parameters` identifies this included subset of actor/main attention, excluding encoders, NOP and targets. Keep local heads free of QCX-shaped slots or memory bypasses. Custom-width builders retain explicit MLP layouts unless residual config is supplied. Fixed MAPPO uses `actor_encoder_config`; custom MAPPO retains its original MLP encoder. Action-output gain remains separate from feature-head gain.
- High-level PPO components use uniform base LR unless explicit `parameter_lr_multipliers` are supplied. Original MAT internal feature/attention gains match common defaults, with small gain only at prediction readouts; its decoder remains post-norm. Plain PPO forwards common feature/readout gains and PopArt beta/init sigma separately; low-level PPO readout default remains independent. MAT-DEC and MAPPO construct complete actors before their different critic encoders, preserving identical actors under matching seeds. QCX context-token normalization defaults to enabled and must be forwarded explicitly by each builder.
- NOP transition FF depth is shared by PPO/off-policy configs through `transition_model_num_feedforward_hidden_layers`. Deeper transitions reuse MAT encoder blocks so initialization, activations and additive FF accounting include every hidden layer; default one-hidden-layer transitions retain the standard PyTorch encoder. Transition masks require at least one active agent per row/step; sampler padding uses `True`, and the hot path omits value checks to avoid CUDA synchronization. The 10M layouts share one NOP core independent of policy encoder depth.
- TMASAC QCX owns its output head through `actor_head_config.hidden_dims`; its nested decoder's `actor_head_hidden_dims` must stay `None`. Shared decoder scaling must leave the MAT-specific output-head override to the on-policy builder.
- `rmat_temporal_model_cls/config` supply shared temporal defaults. `rmat_critic_temporal_model_cls/config` independently override recurrent MAT/TD3 critics; both fixed critic families use `critic_temporal_hidden_dim`. Per-layer lists must match each resolved encoder depth; fixed actor/critic depths agree, while custom layouts can differ. Fixed actor memory widths use multiples of eight instead of single-unit budget tuning. TMASAC sLSTM defaults to four heads; scalar, per-layer and mixed class specifications containing sLSTM all select its headwise memory width. Matching recurrent totals must account for input adapters becoming identities when memory width equals token width.
- Deep Set/transformer off-policy critics share embedding/local processing and private Q-head construction (`build_q_network`). Gated Deep Set presets gate critic encoders; independent Q-head gating uses `critic_deepset_head_gating` (default false). Explicit low-level head configs can also enable gates. Single critics retain one ordinary head with the same widths/depth as each twin head; never enlarge a V or Q head to compensate for a missing second head. Fixed pooled V/Q heads share `critic_head_width`, 1.25D messages and 2D local hidden widths for approximately equal global/local interaction parameters; explicit local-width overrides remain authoritative. Original MAT sizes its distinct readout against one head. Independent encoders duplicate capacity without resizing. Copied message/gate weights need independent initialization. NOP consumes masked pre-head features once, concatenating only independent encoders; re-encoding must pass `agent_mask`. Flattened MLP critics reject NOP; off-policy Deep Set heads reject PopArt.
- `mappo__deepset_critic` replaces `mappo` without aliases or migrations, keeping `v1` for fresh runs. It combines a public-only local actor (fixed scales use MAT encoder blocks with MLP attention replacements; custom widths use `mappo_encoder.py`) with `DeepSetEncoder` (`algos/mat/deep_set_encoder.py`), whose blocks also serve off-policy critics. Public and privileged fields enter critic embeddings together via `mat/independent_encoders.py`; `make_value_head` shares MAT's pooled V head, receiving encoded features only. Actor and critic widths are independent; an explicit `actor_encoder_config.d_model` determines the actor-head input width. Shared PPO actor hooks must pass `agent_mask` to optional MAPPO MAT encoders. NOP uses critic features; value/NOP gradients never update the actor, and inference runs only the needed encoder. Fixed scales share critic width/depth/FF with MAT/off-policy and preserve 40% actor / 60% critic budgets; expanding messages add under 1% versus MAT's critic count. Plain PPO retains the shared MLP backbone and late privileged inputs. `PPOPolicy._evaluate_critic` centralizes its value/latent path and MAPPO overrides that path for early privileged inputs.
- Raw-input LayerNorm erases scalar signals; preserve observation/action features before projection. Feature-wise observation normalization and learned-feature normalization are separate.
- Empty attention key sets need safe masking before attention/softmax, then zero attention contribution. Native MHA's eval/no-grad fast path can return NaNs for all-inactive rows; `nn_components/attention.py` handles safe padding masks for MAT/RMAT. Original MAT also sanitizes empty softmax logits because masking only the output leaves non-finite backward gradients.
- Checkpoints use only the current format: no migrations, missing-buffer repairs, wrapper aliases or historical import shims. Compiled/uncompiled key alignment remains supported. Reconstruction requires matching task, layout/version, distribution, NOP and structural settings. Changed observation layouts can invalidate checkpoints even when shapes match. Recurrent TD3 additionally needs `td3_recurrent_actor` and the original `td3_recurrent_critic` setting.
- Loading must restore the base LR from checkpoint hyperparameters as well as LR controllers/custom schedulers and their enabled state, not just Adam LR; warmup rates are derived from that base. Off-policy replay is not checkpointed. gSDE schedules live in `gsde_reset.py`, persist in algorithm `hyper_parameters`, and are required when recording a gSDE checkpoint; initialize noise before masked resets.

## Learning and evaluation

- PPO/off-policy rollout-device changes move environment wrappers, cached observations, recurrent histories and exploration noise together. gSDE noise is a nonpersistent buffer: module device moves include it, checkpoints omit it.
- SAME_STEP returns reset observations; terminals are `final_obs` selected by `_final_obs`. Truncation bootstrap uses terminals; recurrent PPO requires TBPTT. Observation buffers are reused: retained data needs copies; integer-indexed reset writes must assign back to source tensors.
- `base_policy.policy_inference_step` brackets complete PPO/MAPPO/MAT/RMAT CUDA graph inference and snapshots outputs before subsequent calls reuse storage. Boundaries stay outside compiled submodules.
- PPO collects fixed-step rollouts and rejects core-policy dropout; NOP dropout is independent. Entropy regularization belongs to learners: PPO's masked joint-importance-weighted `mc_ent_coef`, SAC temperature tuning. SAC needs pathwise/straight-through sampling; ordinary SMB is for PPO, Gumbel SMB for SAC. Squashed Gaussian likelihoods use stable pre-tanh Jacobians.
- Diagnostics need masks from their own cached parameter batch, captured before replay updates replace it. Exclude recurrent padding/unused truncation successor slots. NOP metrics stay detached on-device until aggregation; reusable compiled outputs need snapshots.
- TD3/SAC delays use persistent update counters; SAC delay also gates temperature. Critic NOP updates each step, actor NOP follows actor delay. Recurrent TD3 preserves separate online/target actor histories; critics consume matching detached states. Candidate-action branches must not overwrite executed-action history.
- `presets/off_policy.py` owns shared high-level SAC/DDPG/TD3 optimization and recurrent replay defaults. `make_training` uses a fixed 1,024-position batch budget, converting recurrent batches to whole sequences after horizon overrides. Explicit `batch_size` overrides count sequences for recurrent learners and transitions otherwise; burn-in is outside the scored-position budget. Replay capacity uses one common rule with a recurrent segment-storage minimum; low-level learner constructors retain independent defaults.
- Recurrent off-policy replay permits at most one truncation in the scored learning suffix, with no such limit in burn-in. `make_training` warns for `episode_length < learning_steps`; repeated timeouts within half the learning horizon prevent sampling any learning windows. Genuine terminations do not count toward this restriction.
- `train` saves/closes; `make_training` leaves closing to the caller. Example scripts require fresh output directories; Python supports continuation. `total_timesteps` is an absolute final counter. Default run metadata omits training seed/commit; the training example's `evaluation.json` records seed and final steps.
- A fresh `as_benchmark_policy` per evaluation/recording owns temporal/action/noise state and freezes normalization without mutating training statistics. It shares the actor: no concurrent training. Scenario-conditioned evaluation needs explicit `scenario_id`; supplied IDs win, and public globals are padded before normalization.
- `gsde_reset.reset_gsde_noise` shares noise initialization and scheduled resets across off-policy rollout, benchmark adapters and frozen evaluation. `ScheduledEvaluationHook` forwards the current trainer schedule on every evaluation; direct `FrozenEvaluationRunner.evaluate` calls require `gsde_reset_mode` for gSDE policies.
- Protocol evaluation takes the first episode per lane in lane order, requiring `num_episodes <= num_envs`. Recording recycles lanes, discards interrupted episodes, closes environments and waits for writers. Actors may combine public observations across agents, never privileged fields. Evaluation seeds sample the existing morphology pool, not unseen morphologies.
- Logging console/persistence profiles are independent. Filtering follows aggregation; preserve scenario-success presence masks, CSV columns/history and restored compressed logs.
- Numerical diagnostics prioritize ordinary training ranges. Artificial huge/tiny floats and exact integer preservation beyond float64 precision are accepted low-priority limits. Keep basic non-finite handling; pursue broader precision work only when real workloads need it.
- The standalone PPO example stays independent of `swarmbots.learn`; stored pre-tanh samples avoid inverse-tanh saturation because squash Jacobians cancel in PPO ratios. Biasless PopArt needs its offset; zero-angle rotation gradients need analytic sinc coefficients.

## Simulator invariants

- `MJWSwarmBotsVectorEnv` prepends raw active-agent count at `hidden_global_vars[..., 0]`; scenario fields start at 1. Normalization leaves the count raw; critics must not append it again. Joint/observation hinge counts derive from `mjw_env/swarm/unit.py`.
- `_prepare_world_reset` owns shared reset sampling/application; `_reset_worlds` applies the prepared reset immediately. Positive settling uses CPU-settled snapshots; zero disables it. Reseeding clears prefetch; pool changes invalidate pending snapshots. FIFO reservations include ready/queued/in-flight work: worker timing must not change sampling order. Preserve shuffle/shared RNG streams during device setup and partial reseeding.
- Core environments accept `SAME_STEP` (default) or `NEXT_STEP`; learning wrappers still reject other modes. `NEXT_STEP` returns terminal observations directly; the following reset-only call ignores actions and zeros rewards/flags. Its pending mask is `None` unless worlds await reset, avoiding extra tensor work/synchronization on ordinary steps. Clone done flags only on actual terminations/truncations, and drop the mask when explicit resets clear its last bit. Warp advances the full batch: `_prepare_world_reset` samples once, applies before physics to remove terminal/unstable state, then reapplies the identical reset after physics to preserve initial state/scenario baselines without extra RNG draws. Partial resets clear only selected bits. Observation rebuilds retain error masking until failed worlds reset; `_unstable_observation_mask` owns a clone only after an actual instability because compiled outputs can reuse storage. Keep recorder starts after restoration and instance metadata separate from the class default.
- Swarms own copies of location configurations because active pool size is mutable runtime state; reusing constructor inputs must not couple environments or skip settled-reset invalidation. Multi-scenario pool-size updates call every child's `validate_active_swarm_pool_size` before any setter, including capacity and pending-step restrictions; rejected changes must preserve active sizes and reset snapshots.
- First-episode staggering belongs in training construction, outside `_make_policy_env`, so evaluation/recording retain full episodes. Explicit first-episode keys, including `None`, suppress generated limits; staggering uses a separate RNG.
- Wall resets intentionally include partially solved assemblies; milestones latch without retroactive rewards. Live reward commands accept only declared `reward_weights` and validate all scenario children before mutation; other reward settings affect cached potentials.
- Connector frames always use surface positioning. Pool grounding uses `get_unit_rest_min_z`, assuming zero hinge angles and yaw-only resets; numeric `z_pos` retains fixed-height offset semantics. Payload spacing needs shape-aware footprints and float32 clearance at actual sampled origins.
- CUDA runtime/reset work follows PyTorch's current stream; physics capture uses a capturable Warp stream and `data.qpos.device`. Padded model templates are separate from sampled assemblies. Different task shapes share Dynamo caches: isolate processes or reset compiler state after closing environments, never silently reset callers' policies.

## Tools and release hazards

- Diagram generation inspects current policies every invocation. Only explanatory guides are tracked; generated counts/reports/diagrams are excluded by Git and `MANIFEST.in`. `.github/workflows/policy-diagrams.yml` builds all variants/scales on relevant `main` pushes or manual runs into `.tmp/pages/policy-diagrams`, publishing `.tmp/pages` with the viewer at `/swarm-bots/policy-diagrams/` and a root redirect; inspection reports stay outside the site. Repository Settings → Pages must use GitHub Actions as the source. No snapshots or `--refresh`. Integration tests cache metadata per variant/scale.
- Architecture/name edits and diagram tests do not refresh existing ignored local renders. Rebuild with `.venv/Scripts/python.exe -m swarmbots.tools.diagram_policy_architectures --include-hidden`; renamed variants/scales can leave obsolete files beside the rebuilt gallery and need cleanup.
- Diagram `ComponentBlock` insets contain repeated operations/inclusive subtotals; outer `Node` boxes own additive counts. One-time projections/readouts stay outside repeated blocks. `policy_diagram_layout.py` owns shared SVG/Pillow geometry and reserved routing space; `connection_paths` adds solid crossing jumps shared by both renderers. Paint all paths before all bridge overlays: sorting whole jumping paths cannot handle crossings between them. Touching arcs need duplicate-point removal before raster dashing. Registered-preset geometry tests compare every arrow pair, including segment endpoints: node/label clearance alone misses crossings. Recurrent actions-to-critic routing permits one perpendicular crossing of the actor-state connection to avoid a detour around NOP; other intersections and all overlaps remain forbidden.
- Plotting imports Matplotlib lazily, preserves the caller's backend and direct `plot_logs` export despite the module-name collision. All curve paths sort and keep last finite duplicate-X before smoothing, preserving individual gaps. Aggregation interpolates finite ranges without extrapolation, applies cutoff first, and uses population std; contributing seed counts vary with X.
- CUDA dependencies are pinned together in the source `cuda` group; published metadata uses standard PyTorch. CPU CI needs EGL (`MUJOCO_GL=egl`); OSMesa caused native crashes. Installed-wheel checks run outside the checkout; CPU CI does not cover CUDA.
- Windows sandbox caches belong under `.tmp` (`TEMP`/`TMP`, Inductor, Warp). Python 3.13's `0o700` temp ACLs may exclude the sandbox identity; local `.tmp/sitecustomize.py` can map mkdir to `0o777`, inherited through `PYTHONPATH`. Never package this workaround.
- CUDA fault-injection tests should use `unittest.mock.patch.object` when replacing inherited instance methods. Pytest's instance `monkeypatch.setattr` restores a bound method into the instance, creating a self-cycle; deferred GC can then destroy closed environments' GPU resources during a later Warp graph capture.
- Release: unused alpha via `uv version <version> --no-sync`; align CITATION/README pin/dated changelog. Run `uv sync --locked --extra dev`, release metadata tests, CUDA tests (`.venv/Scripts/python.exe -m pytest -m cuda`) and `git diff --check`; stop on failure. Review/stage intended changes, commit/push main, then push an annotated version tag.
- **Tag pushes publish to PyPI** through `.github/workflows/release.yml`. Verify publication; corrections require a new version, never overwritten tags/distributions. Contributor/release procedures stay out of public docs.
