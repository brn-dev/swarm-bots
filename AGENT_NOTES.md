## Policy and checkpoint invariants

- Preset names use `base_variant__modifier`: architecture names retain single underscores (`mat_qcx`, `tmasac_dec`); modifiers use double underscores (`mat_qcx__lstm`, `masac__deepset_critic`). Removed names have no aliases. Registry membership comes from `variants.py`; retained low-level builders are not necessarily public presets. Actor/critic encoder sharing differs from sharing between Q heads.
- Model scales are fixed, versioned, task-independent declarations, never runtime fitting. `5M-2L` replaces rejected `5M` aliases; the 10M family is `10M-3L`/`10M-4L`/`10M-5L`. Depth choices retain comparable actor/critic budgets and the NOP core, splitting on-policy actor depth between encoder and head while adjusting FF/memory widths. The 5M actors use D=320 at 2L and D=256 at 3L across MAT/MAPPO/off-policy families; plain PPO stays fixed. The 3L layout derives from 2L with explicit overrides for width-dependent actor fields, so changes to the base must preserve 3L's budget. Off-policy FF-only actor depth stays fixed, with matched budgets across widths; 10M FF-only actors retain the same complete architecture across depths. Registry order is budget then depth and also controls gallery order. Recurrence/gates add capacity. Fixed widths override custom widths but preserve explicit structural configs; `model_scale=None` / CLI `custom` enables explicit widths. `ScaleLayout.slug` separates equal-budget layouts.
- MAT owns independent actor/critic encoders: `encoder_config` is actor, `critic_encoder_config` critic. RMAT state maps `actor`/`critic` histories; rollout advances both, inference actor only, bootstrap critic only. MAT/RMAT NOP consumes the attached critic-encoder output from the same evaluation pass; use `nop_latent_dim` for its source width. Recurrent NOP follows critic history, not actor history. Compiled joint evaluation may materialize zero gradients for unused outputs; isolation tests check zero gradients and unchanged weights. Recurrent MAT adds memory to the unchanged feed-forward backbone. Recurrent TMASAC actors use attention → one-hidden-layer MLP → memory → one-hidden-layer MLP; fixed `recurrent_actor_ff_width` gives each MLP half the ordinary FF parameter budget. Critic FF stays intact; state adapters use actual temporal `hidden_dim`, not token width. Fixed TMASAC layouts match LSTM/sLSTM complete main counts through different memory widths.
- MAT/RMAT critic observation inputs include privileged local/global fields before embedding, attention and recurrence; value heads consume only encoded features. `mat/independent_encoders.py` owns input assembly for rollout, sequence training and critic-side NOP. Fixed critic dimensions use the same scale builder as off-policy critics, with a separate `critic_temporal_hidden_dim` for recurrent MAT. Actors remain public-only.
- Fixed MAT/MAPPO actors split the 1M/2M/4M actor budget roughly equally between encoder and head. IND/QCX/Orig actor encoders are identical; IND/DEC/MAPPO heads use three-linear-layer stages with matched complete decoder/head counts. `mat_encoder_layers + decoder_layers` is the nominal 2L/3L/4L/5L depth (1+1/2+1/2+2/3+2); it counts processing stages, not every affine operation. Recurrent IND/QCX share `mat_actor_temporal_hidden_dim`. Original MAT's decoder FF width is configurable. Fixed MAPPO actor encoders normalize learned features after each activation to avoid attenuation through deep MLPs; raw observations remain untouched. Its small initialization gain belongs to `action_net_init_gain`, after the feature head.
- NOP transition FF depth is shared by PPO/off-policy configs through `transition_model_num_feedforward_hidden_layers`. Deeper transitions reuse MAT encoder blocks so initialization, activations and additive FF accounting include every hidden layer; default one-hidden-layer transitions retain the standard PyTorch encoder. The 10M layouts share one NOP core independent of policy encoder depth.
- TMASAC QCX owns its output head through `actor_head_config.hidden_dims`; its nested decoder's `actor_head_hidden_dims` must stay `None`. Shared decoder scaling must leave the MAT-specific output-head override to the on-policy builder.
- `rmat_temporal_model_cls/config` supply shared temporal defaults. `rmat_critic_temporal_model_cls/config` independently override recurrent MAT/TD3 critics. Per-layer lists must match each resolved encoder depth; MAT actor and critic depths differ at fixed scales, so heterogeneous stacks need separate lists. Fixed TMASAC sLSTM memory widths retain divisibility by eight alongside the default four heads; scalar, per-layer and mixed class specifications containing sLSTM all select that width.
- Deep Set/transformer off-policy critics share embedding/local processing and private Q-head construction (`build_q_network`). Gated Deep Set presets gate critic encoders; independent Q-head gating uses `critic_deepset_head_gating` (default false). Explicit low-level head configs can also enable gates. Independent encoders duplicate capacity without resizing. Copied message/gate weights need independent initialization. NOP consumes masked pre-head features once, concatenating only independent encoders; re-encoding must pass `agent_mask`. Flattened MLP critics reject NOP; off-policy Deep Set heads reject PopArt.
- `mappo__deepset_critic` replaces `mappo` without aliases or migrations, keeping `v1` for fresh runs. It combines a public-only local MLP actor (`mappo_encoder.py`) with `DeepSetEncoder` (`algos/mat/deep_set_encoder.py`), whose blocks also serve off-policy critics. Public and privileged fields enter critic embeddings together via `mat/independent_encoders.py`; `make_value_head` shares MAT's pooled V head, receiving encoded features only. `actor_config.latent_dim` and `critic_encoder_config.d_model` are independent. NOP uses critic features; value/NOP gradients never update the actor, and inference runs only the needed encoder. Fixed scales share critic width/depth/FF with MAT/off-policy and preserve 40% actor / 60% critic budgets; expanding messages add under 1% versus MAT's critic count. Plain PPO retains the shared MLP backbone and late privileged inputs. `PPOPolicy._evaluate_critic` centralizes its value/latent path and MAPPO overrides that path for early privileged inputs.
- Raw-input LayerNorm erases scalar signals; preserve observation/action features before projection. Feature-wise observation normalization and learned-feature normalization are separate.
- Checkpoints use only the current format: no migrations, missing-buffer repairs, wrapper aliases or historical import shims. Compiled/uncompiled key alignment remains supported. Reconstruction requires matching task, layout/version, distribution, NOP and structural settings. Changed observation layouts can invalidate checkpoints even when shapes match. Recurrent TD3 additionally needs `td3_recurrent_actor` and the original `td3_recurrent_critic` setting.
- Loading must restore the base LR from checkpoint hyperparameters as well as LR controllers/custom schedulers and their enabled state, not just Adam LR; warmup rates are derived from that base. Off-policy replay is not checkpointed. gSDE schedules live in `gsde_reset.py`, persist in algorithm `hyper_parameters`, and are required when recording a gSDE checkpoint; initialize noise before masked resets.

## Learning and evaluation

- PPO/off-policy rollout-device changes move environment wrappers, cached observations, recurrent histories and exploration noise together. gSDE noise is a nonpersistent buffer: module device moves include it, checkpoints omit it.
- SAME_STEP returns reset observations; terminals are `final_obs` selected by `_final_obs`. Truncation bootstrap uses terminals; recurrent PPO requires TBPTT. Observation buffers are reused: retained data needs copies; integer-indexed reset writes must assign back to source tensors.
- `base_policy.policy_inference_step` brackets complete MAT/RMAT CUDA graph inference and snapshots outputs before subsequent calls reuse storage. Boundaries stay outside compiled submodules.
- PPO collects fixed-step rollouts and rejects core-policy dropout; NOP dropout is independent. Entropy regularization belongs to learners: PPO's masked joint-importance-weighted `mc_ent_coef`, SAC temperature tuning. SAC needs pathwise/straight-through sampling; ordinary SMB is for PPO, Gumbel SMB for SAC. Squashed Gaussian likelihoods use stable pre-tanh Jacobians.
- Diagnostics need masks from their own cached parameter batch, captured before replay updates replace it. Exclude recurrent padding/unused truncation successor slots. NOP metrics stay detached on-device until aggregation; reusable compiled outputs need snapshots.
- TD3/SAC delays use persistent update counters; SAC delay also gates temperature. Critic NOP updates each step, actor NOP follows actor delay. Recurrent TD3 preserves separate online/target actor histories; critics consume matching detached states. Candidate-action branches must not overwrite executed-action history.
- `presets/off_policy.py` owns shared high-level SAC/DDPG/TD3 optimization and recurrent replay defaults. `make_training` uses a fixed 1,024-position batch budget, converting recurrent batches to whole sequences after horizon overrides. Explicit `batch_size` overrides count sequences for recurrent learners and transitions otherwise; burn-in is outside the scored-position budget. Replay capacity uses one common rule with a recurrent segment-storage minimum; low-level learner constructors retain independent defaults.
- `train` saves/closes; `make_training` leaves closing to the caller. Example scripts require fresh output directories; Python supports continuation. `total_timesteps` is an absolute final counter. Default run metadata omits training seed/commit; the training example's `evaluation.json` records seed and final steps.
- A fresh `as_benchmark_policy` per evaluation/recording owns temporal/action/noise state and freezes normalization without mutating training statistics. It shares the actor: no concurrent training. Scenario-conditioned evaluation needs explicit `scenario_id`; supplied IDs win, and public globals are padded before normalization.
- Protocol evaluation takes the first episode per lane in lane order, requiring `num_episodes <= num_envs`. Recording recycles lanes, discards interrupted episodes, closes environments and waits for writers. Actors may combine public observations across agents, never privileged fields. Evaluation seeds sample the existing morphology pool, not unseen morphologies.
- Logging console/persistence profiles are independent. Filtering follows aggregation; preserve scenario-success presence masks, CSV columns/history and restored compressed logs.
- Numerical diagnostics prioritize ordinary training ranges. Artificial huge/tiny floats and exact integer preservation beyond float64 precision are accepted low-priority limits. Keep basic non-finite handling; pursue broader precision work only when real workloads need it.
- The standalone PPO example stays independent of `swarmbots.learn`; stored pre-tanh samples avoid inverse-tanh saturation because squash Jacobians cancel in PPO ratios. Biasless PopArt needs its offset; zero-angle rotation gradients need analytic sinc coefficients.

## Simulator invariants

- `MJWSwarmBotsVectorEnv` prepends raw active-agent count at `hidden_global_vars[..., 0]`; scenario fields start at 1. Normalization leaves the count raw; critics must not append it again. Joint/observation hinge counts derive from `mjw_env/swarm/unit.py`.
- All resets share `_reset_worlds`. Positive settling uses CPU-settled snapshots; zero disables it. Reseeding clears prefetch; pool changes invalidate pending snapshots. FIFO reservations include ready/queued/in-flight work: worker timing must not change sampling order. Preserve shuffle/shared RNG streams during device setup and partial reseeding.
- First-episode staggering belongs in training construction, outside `_make_policy_env`, so evaluation/recording retain full episodes. Explicit first-episode keys, including `None`, suppress generated limits; staggering uses a separate RNG.
- Wall resets intentionally include partially solved assemblies; milestones latch without retroactive rewards. Live reward commands accept only declared `reward_weights` and validate all scenario children before mutation; other reward settings affect cached potentials.
- Connector frames always use surface positioning. Pool grounding uses `get_unit_rest_min_z`, assuming zero hinge angles and yaw-only resets; numeric `z_pos` retains fixed-height offset semantics. Payload spacing needs shape-aware footprints and float32 clearance at actual sampled origins.
- CUDA runtime/reset work follows PyTorch's current stream; physics capture uses a capturable Warp stream and `data.qpos.device`. Padded model templates are separate from sampled assemblies. Different task shapes share Dynamo caches: isolate processes or reset compiler state after closing environments, never silently reset callers' policies.

## Tools and release hazards

- Diagram generation inspects current policies every invocation. Only explanatory guides are tracked; generated counts/reports/diagrams are excluded by Git and `MANIFEST.in`. `.github/workflows/policy-diagrams.yml` builds all variants/scales on relevant `main` pushes or manual runs into `.tmp/pages/policy-diagrams`, publishing `.tmp/pages` with the viewer at `/swarm-bots/policy-diagrams/` and a root redirect; inspection reports stay outside the site. Repository Settings → Pages must use GitHub Actions as the source. No snapshots or `--refresh`. Integration tests cache metadata per variant/scale.
- Architecture/name edits and diagram tests do not refresh existing ignored local renders. Rebuild with `.venv/Scripts/python.exe -m swarmbots.tools.diagram_policy_architectures --include-hidden`; renamed variants/scales can leave obsolete files beside the rebuilt gallery and need cleanup.
- Diagram `ComponentBlock` insets contain repeated operations/inclusive subtotals; outer `Node` boxes own additive counts. One-time projections/readouts stay outside repeated blocks. `policy_diagram_layout.py` owns shared SVG/Pillow geometry and reserved routing space.
- Plotting imports Matplotlib lazily, preserves the caller's backend and direct `plot_logs` export despite the module-name collision. All curve paths sort and keep last finite duplicate-X before smoothing, preserving individual gaps. Aggregation interpolates finite ranges without extrapolation, applies cutoff first, and uses population std; contributing seed counts vary with X.
- CUDA dependencies are pinned together in the source `cuda` group; published metadata uses standard PyTorch. CPU CI needs EGL (`MUJOCO_GL=egl`); OSMesa caused native crashes. Installed-wheel checks run outside the checkout; CPU CI does not cover CUDA.
- Windows sandbox caches belong under `.tmp` (`TEMP`/`TMP`, Inductor, Warp). Python 3.13's `0o700` temp ACLs may exclude the sandbox identity; local `.tmp/sitecustomize.py` can map mkdir to `0o777`, inherited through `PYTHONPATH`. Never package this workaround.
- Release: unused alpha via `uv version <version> --no-sync`; align CITATION/README pin/dated changelog. Run `uv sync --locked --extra dev`, release metadata tests, CUDA tests (`.venv/Scripts/python.exe -m pytest -m cuda`) and `git diff --check`; stop on failure. Review/stage intended changes, commit/push main, then push an annotated version tag.
- **Tag pushes publish to PyPI** through `.github/workflows/release.yml`. Verify publication; corrections require a new version, never overwritten tags/distributions. Contributor/release procedures stay out of public docs.
