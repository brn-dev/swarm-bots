# Agent notes

- This repository packages the benchmark and built-in learning algorithms in `swarmbots/learn`. Public documentation describes this package's APIs and defaults directly; optional background material is linked from the README. CITATION.cff identifies the benchmark software. Optional W&B and interactive prompts are extras, not base dependencies.
- Public learning helpers are lazily exported by `swarmbots.learn`: `list_variants`, `make_training`, `train`, `as_benchmark_policy`, and `record_checkpoint`. `presets/variants.py` is the sole public preset registry; internal policy-builder kinds are not automatically exposed. `presets/tmasac.py` resolves recurrent/shared architecture and replay settings; `presets/policy_factory.py` holds policy construction and wrapper plumbing. Recurrent names use module suffixes (`mat_ind_lstm`, `tmasac_slstm`); old development names are not aliases. `mappo` builds MAPPO; the former attention-disabled MAT-IND preset is `mat_ind_no_attention`. Policy capacity comes from the task's agent count.
- MAT-IND, MAT-DEC, and QCX share `MATCriticConfig` from `algos/mat_qc_base_policy.py`. `tmasac_dec` selects the existing decentralized actor head kind: per-agent residual MLP blocks without agent attention, using local plus non-privileged global observations. Only actor attention is disabled; the transformer twin critic, NOP, and optimizer settings match `tmasac`.
- TMASAC sLSTM presets enable the temporal residual connection, including their no-NOP, shared-encoder, and SwiGLU variants. `tmasac_slstm_no_residual` is the ablation that disables it.
- Action distributions are independent of variant names: on-policy presets default to `sign_magnitude_beta`; SAC presets default to `predicted_std_gaussian`. Explicit overrides use `continuous_action_dist`. The Gaussian module/classes are `predicted_std_gaussian_action_dist`, `PredictedStdGaussianConfig`, and `PredictedStdGaussianActionDist`. Rebuilding an SMB-trained SAC checkpoint requires the matching Gumbel SMB override rather than the Gaussian default.
- Keep the public distribution set limited to SMB, Gumbel SMB, Beta, predicted STD Gaussian, gSDE, squashed diagonal Gaussian, and discrete categorical/Bernoulli support. Experimental quantile, spline, mixture, Kumaraswamy, ternary, and sticky implementations are excluded. SAC supports multiple independent actor/target action samples; quantile-only stratification and stickiness interfaces are removed. `test_release_metadata.py` guards the packaged distribution inventory.
- The convenience trainer uses benchmark task defaults (including 500 control steps and settled resets), eager modules by default, and no rollout warmup or initial episode staggering. Architectures/optimizer settings remain customizable through `policy_kwargs`/`algorithm_kwargs`. `train` saves through the normal learner and closes its environment; `make_training` transfers close responsibility to the caller.
- Learning wrappers and rollout/replay use SAME_STEP. PPO truncation bootstrap reads `final_obs`; recurrent replay retains episode reset masks and burn-in. Recurrent PPO requires the TBPTT sampler even without NOP. SAC uses physical replay actions and requires distributions with pathwise/straight-through actor gradients; ordinary categorical SMB is for PPO, Gumbel SMB for SAC.
- PPO optimizer checkpoints include adaptive LR controller state and its enabled flag; restoring only Adam's learning rate can restart canceled warmup. Legacy checkpoints without controller metadata retain constructor defaults. The convenience trainer derives the controller's KL threshold from the resolved PPO `target_kl`.
- `as_benchmark_policy` sends only non-privileged fields to the actor and freezes normalization without changing training RMS. It owns recurrent/previous-action/distribution state, preserves each submodule's train/eval mode, and converts packed actions to the simulator dictionary. Create a fresh adapter per evaluation and use the same device as its policy. The actor is shared; do not train concurrently with evaluation.
- `swarmbots.record_policy` and `swarmbots.learn.record_checkpoint` use live exact-state episode recording, close their environments, and wait for MP4 writers. `swarmbots record`/`examples/record_policy.py` support checkpoints or custom `module:factory` callables. Checkpoint recording shares `training._make_policy_env` with the trainer to avoid allocating replay/optimizer state; callers must provide matching task/architecture/distribution/NOP settings. Unlike benchmark scoring, recordings recycle lanes to finish the requested video count.
- Public construction and evaluation live in `swarmbots/benchmark`. Evaluation accepts one episode per lane, preserves lane order, and rejects `num_episodes > num_envs`. Repeated early-finishing lanes must never displace slow lanes. Metadata serialization preserves distribution dataclass types and resolved settings.
- Protocol 0.1 permits centralized, partially centralized, and decentralized actors to combine non-privileged observations across agents within a world. Do not equate the privileged-observation boundary with a decentralized-execution requirement. The Gymnasium interface returns device-resident PyTorch tensors; NumPy-based wrappers require adaptation.
- Registry defaults share morphology pool seeds 42000–42049. Evaluation seeds change sampling, not pool membership. Protocol 0.1 does not claim held-out-morphology generalization.
- Environments use SAME_STEP autoreset. Terminal observations are in `final_obs`, selected by `_final_obs`; returned observations belong to reset episodes. Observation buffers may be reused. Indexed reset writes must assign back to their source tensor: integer-indexed selections are copies, not views.
- Explicit, partial, and automatic resets share `_reset_worlds` and use CPU-settled snapshots whenever `reset_settle_time > 0`. Seeded resets clear prefetched snapshots before reseeding. The one-shot `settle_initial_reset` API was removed; disable settling for custom variants with `reset_settle_time=0`. Protocol 0.1 uses settled first episodes; scores from the earlier unsettled-first-episode behavior need rerunning. The task matrix tests default settling; lifecycle tests cover staggered episodes with the async buffer and CUDA's full 500-step limit.
- CI is reusable via `workflow_call`; release builds depend on it. CPU jobs install the EGL dispatch library and Mesa runtime (`libegl1`, `libegl-mesa0`, `libgl1-mesa-dri`) and set `MUJOCO_GL=egl` for tests and installed-wheel checks. Missing EGL causes a MuJoCo import error; switching to OSMesa instead caused a native crash while importing Triton in both Python jobs. Installed-wheel checks must execute outside the checkout. CPU CI skips CUDA tests; release GPU checks are documented in `docs/publishing.md`.
- Warp graph capture must use `data.qpos.device`; MuJoCo Warp's Model has no qpos field. This path is CUDA-only and is invisible to CPU integration tests.
- Different task observation shapes share Dynamo's function cache. A full 14-task sweep can exhaust its specialization limit. GPU tests reset compiler state between cases; use one process per task/configuration or explicitly reset compiler state after closing the previous environment. Do not silently reset callers' compiled policy state inside the environment.
- Use `.venv/Scripts/python.exe` on Windows. In the managed Windows sandbox, redirect TEMP/TMP and TORCHINDUCTOR_CACHE_DIR into pre-created `.tmp` directories. Python 3.13 creates temporary directories with restrictive 0o700 ACLs that exclude the sandbox identity. For sandbox-only validation, a `.tmp` sitecustomize.py can wrap os.mkdir to replace 0o700 with 0o777 on Windows; set PYTHONPATH to that directory for subprocess builds too. Never ship that workaround in the package.
- For sandboxed CLI runs outside pytest, also set `WARP_CACHE_PATH` to a writable `.tmp` directory; otherwise Warp compilation fails with `PermissionError` in the default AppData cache. The pytest fixture already redirects its own Warp cache.
