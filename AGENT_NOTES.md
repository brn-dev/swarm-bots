# Agent notes

- This repository is the standalone benchmark. Training algorithms and thesis experiments live in the sibling `swarm-bots-research` repository; do not introduce dependencies on that checkout.
- Public construction and evaluation live in `swarmbots/benchmark`. Evaluation accepts one episode per lane, preserves lane order, and rejects `num_episodes > num_envs`. Repeated early-finishing lanes must never displace slow lanes. Metadata serialization preserves distribution dataclass types and resolved settings.
- Protocol 0.1 permits centralized, partially centralized, and decentralized actors to combine non-privileged observations across agents within a world. Do not equate the privileged-observation boundary with a decentralized-execution requirement. The Gymnasium interface returns device-resident PyTorch tensors; NumPy-based wrappers require adaptation.
- Registry defaults share morphology pool seeds 42000–42049. Evaluation seeds change sampling, not pool membership. Protocol 0.1 does not claim held-out-morphology generalization.
- Environments use SAME_STEP autoreset. Terminal observations are in `final_obs`, selected by `_final_obs`; returned observations belong to reset episodes. Observation buffers may be reused. Indexed reset writes must assign back to their source tensor: integer-indexed selections are copies, not views.
- Explicit, partial, and automatic resets share `_reset_worlds` and use CPU-settled snapshots whenever `reset_settle_time > 0`. Seeded resets clear prefetched snapshots before reseeding. The one-shot `settle_initial_reset` API was removed; disable settling for custom variants with `reset_settle_time=0`. Protocol 0.1 uses settled first episodes; scores from the earlier unsettled-first-episode behavior need rerunning. The task matrix tests default settling; lifecycle tests cover staggered episodes with the async buffer and CUDA's full 500-step limit.
- CI is reusable via `workflow_call`; release builds depend on it. Installed-wheel checks must execute outside the checkout. CPU CI skips CUDA tests; release GPU checks are documented in `docs/publishing.md`.
- Warp graph capture must use `data.qpos.device`; MuJoCo Warp's Model has no qpos field. This path is CUDA-only and is invisible to CPU integration tests.
- Different task observation shapes share Dynamo's function cache. A full 14-task sweep can exhaust its specialization limit. GPU tests reset compiler state between cases; use one process per task/configuration or explicitly reset compiler state after closing the previous environment. Do not silently reset callers' compiled policy state inside the environment.
- Use `.venv/Scripts/python.exe` on Windows. In the managed Windows sandbox, redirect TEMP/TMP and TORCHINDUCTOR_CACHE_DIR into pre-created `.tmp` directories. Python 3.13 creates temporary directories with restrictive 0o700 ACLs that exclude the sandbox identity. For sandbox-only validation, a `.tmp` sitecustomize.py can wrap os.mkdir to replace 0o700 with 0o777 on Windows; set PYTHONPATH to that directory for subprocess builds too. Never ship that workaround in the package.
- For sandboxed CLI runs outside pytest, also set `WARP_CACHE_PATH` to a writable `.tmp` directory; otherwise Warp compilation fails with `PermissionError` in the default AppData cache. The pytest fixture already redirects its own Warp cache.
