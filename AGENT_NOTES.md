# Agent notes

- This repository packages the benchmark and built-in learning algorithms in `swarmbots/learn`. Public documentation describes this package's APIs and defaults directly; optional background material is linked from the README. CITATION.cff identifies the versioned benchmark software and lists the published thesis under `references`; the thesis URN must not be used as a software identifier. Optional W&B and interactive prompts are extras, not base dependencies.
- Source checkouts use the explicit `pytorch-cu132` index for Windows/Linux and a default `cuda` dependency group that pins the validated PyTorch/Windows Triton pair. Plain syncs, contributor syncs, and `--all-extras` retain this setup. Keep accelerator/compiler pins in this local group: published package metadata uses the standard PyTorch requirement, so application projects select their own accelerator source. Update PyTorch and Windows Triton together when changing compiler versions.
- Public learning helpers are lazily exported by `swarmbots.learn`: `list_variants`, `make_training`, `train`, `as_benchmark_policy`, and `record_checkpoint`. `presets/variants.py` is the sole public preset registry; internal policy-builder kinds are not automatically exposed. `presets/tmasac.py` resolves recurrent/shared architecture and replay settings; `presets/policy_factory.py` holds policy construction and wrapper plumbing. Recurrent names use module suffixes (`mat_ind_lstm`, `tmasac_slstm`); old development names are not aliases. `mappo` builds MAPPO; the former attention-disabled MAT-IND preset is `mat_ind_no_attention`. Policy capacity comes from the task's agent count.
- Public log plotting is exported by `swarmbots.plotting`: `plotting/logs.py` handles compressed CSV reading/discovery and seed aggregation, while `plotting/plot_logs.py` imports Matplotlib only when plotting is invoked, from the optional `plot` extra. Keep the caller's backend. Package exports are bound directly so the `plot_logs` function remains callable despite sharing its name with the module. Grouped curves interpolate finite samples within each run's range, use the last finite duplicate-X sample, and apply cutoffs before interpolation. Per-X counts can fall as short seeds end; shading is population std, not a confidence interval. Default metrics permit missing success EMAs; explicitly selected columns must exist. The scriptable examples are `examples/plot_logs.py` and `examples/plot_experiment_results.py`; CI installs the plot extra to exercise them.
- MAT-IND, MAT-DEC, and QCX share `MATCriticConfig` from `algos/mat_qc_base_policy.py`. `tmasac_dec` selects the existing decentralized actor head kind: per-agent residual MLP blocks without agent attention, using local plus non-privileged global observations. Only actor attention is disabled; the transformer twin critic, NOP, and optimizer settings match `tmasac`.
- `mat_joint_obs_embedding=True` opts MAT/RMAT input encoders and transformer critic token projections into joint local/global fusion; low-level configs use `MATEncoderConfig.joint_obs_embedding`, inherited by RMAT. Separate input normalization is retained. Action-conditioned critics fuse globals after optional observation/action pre-encoders. The default is additive and preserves existing state_dict shapes/keys and initialization order; no new variants are registered. Joint checkpoints require the matching switch when training/loading/recording. Encoders without globals retain their old layout. MAT-Orig already uses joint inputs; PPO/MAPPO are independent of this flag.
- MAPPO Deep Set critics condition element encoders on privileged globals and retain direct global context after pooling. Public globals already enter the shared per-agent encoder; MAPPO NOP still uses those shared non-privileged features. `mappo_critic_context_in_elements=False` (or low-level `MAPPOCriticConfig.context_in_elements=False`) restores the previous critic layout and checkpoint shapes. Tasks without privileged global variables and flattened MAPPO critics retain their existing input layouts.
- `mappo`/`mappo_small` remain the Deep Set presets; `mappo_mlp`/`mappo_mlp_small` select the existing flattened MAPPO critic with hidden widths `[256, 128]`/`[192, 128]`. Actor configurations, PPO settings, NOP defaults, and distribution choices match the corresponding sizes. Unlike off-policy MLP critics, MAPPO MLP retains shared-encoder NOP and supports PopArt. Fixed-slot MLP critics are order sensitive and their input parameter count scales with the padded agent count.
- MADDPG/MATD3/MASAC expose `_mlp` and `_deepset` critic presets; TMATD3 exposes `tmatd3` and `tmatd3_dec`. Deep Set and transformer baselines enable critic NOP by default and support critic/actor/both sources; MLP presets are marked (no NOP) and reject NOP for every source. These baselines omit PopArt. Deep Set critic NOP uses masked per-agent element features before pooling; twin critic features are concatenated. Deep Set baseline element encoders receive global observations, privileged global variables, and cardinality by default, with the same context retained after pooling. `baseline_critic_context_in_elements=False` restores the previous layout and checkpoint shapes. Regular forward passes and independent NOP encoding share `DeepSet.encode_elements`; other Deep Set users retain their existing context placement unless `context_after_pool` is explicitly set. TD3 critic NOP updates every step and actor NOP follows the policy delay. MLP critics include flattened padded local/action/privileged fields and explicit masks; Deep Sets use masked means plus cardinality, with 512-wide default encoders/regressors. TD3/DDPG use the shared off-policy rollout/replay/checkpoint lifecycle with deterministic learning steps and no entropy setup; deterministic policies have no action distribution. TD3 has independent target actors, twin critics, normalized target smoothing, and delayed actor/target updates keyed to the persistent update counter. DDPG uses one critic with no delay/smoothing. These are shared-actor cooperative team objectives, not the original per-agent mixed-reward MADDPG/MATD3 update.
- TMASAC sLSTM presets enable the temporal residual connection, including their no-NOP, shared-encoder, and SwiGLU variants. `tmasac_slstm_no_residual` is the ablation that disables it.
- SAC/DDPG/TD3 now share `algos/off_policy/base_algorithm.py`; TD3 no longer inherits SAC. Shared transformer critics, actor heads, NOP, tensor operations, and recurrent replay/history helpers live in `algos/off_policy`, with historical SAC imports retained. SAC defaults remain delay 1 and target noise/clip 0; opt-in delay gates actor/actor-NOP/temperature updates, while SAC target updates retain their independent interval. Smoothing changes only target Q actions and retains the original sample's entropy log-probability. `critic_independent_encoders` controls transformer Q encoder sharing, defaulting to shared encoders for both TMASAC and TMATD3; True restores independent encoders. `td3_recurrent_actor` enables `RecurrentTD3` for MATD3/TMATD3; `td3_recurrent_critic` requires a recurrent actor and TMATD3. Recurrent TD3 feed-forward critics now receive detached actor state by default through the shared actor_state_critic module; the target critic receives target-actor state. td3_actor_state_critic_input_config=None disables this; recurrent critics use their own history. Standard recurrent TMASAC presets retain their existing actor-state default and explicit ablation/shared-temporal exceptions. Replay anchors carry separate online/target actor states. Recurrent critic candidate branches must not replace replay-action history states.
- Action distributions are independent of variant names: on-policy presets default to `sign_magnitude_beta`; SAC presets default to `predicted_std_gaussian`. Explicit overrides use `continuous_action_dist`. The Gaussian module/classes are `predicted_std_gaussian_action_dist`, `PredictedStdGaussianConfig`, and `PredictedStdGaussianActionDist`. Rebuilding an SMB-trained SAC checkpoint requires the matching Gumbel SMB override rather than the Gaussian default.
- Keep the public distribution set limited to SMB, Gumbel SMB, Beta, predicted STD Gaussian, gSDE, squashed diagonal Gaussian, and discrete categorical/Bernoulli support. Experimental quantile, spline, mixture, Kumaraswamy, ternary, and sticky implementations are excluded. SAC supports multiple independent actor/target action samples; quantile-only stratification and stickiness interfaces are removed. `test_release_metadata.py` guards the packaged distribution inventory.
- The convenience trainer uses benchmark task defaults (including 500 control steps and settled resets), eager modules by default, and no rollout warmup or initial episode staggering. Architectures/optimizer settings remain customizable through `policy_kwargs`/`algorithm_kwargs`. `train` saves through the normal learner and closes its environment; `make_training` transfers close responsibility to the caller.
- All learners select console/persistence presets independently via `BaseAlgorithm.learn(logging_console_level=..., logging_persistence_level=...)`, defaulting to `minimal`/`full`. `learn/logging_levels.py` owns `full`, `minimal`, and `return_success` profiles and console aliases. Filtering happens after buffered aggregation and before CSV/W&B serialization, preserving all statistics for retained metrics; reduced persistence also retains scenario-prefixed outcomes/counts and the W&B step key. Existing CSV headers/history survive a level change on resume. `logging_console_keys="default"` follows the console preset, explicit `None` shows all, and `[]` silences metric rows. Custom selections override only the console preset and retain one-time missing-key warnings. Console loss formats use `SummaryStatisticsFormat`; LR formats support scalar/list/dict rates.
- Learning wrappers and rollout/replay use SAME_STEP. PPO truncation bootstrap reads `final_obs`; recurrent replay retains episode reset masks and burn-in. Recurrent PPO requires the TBPTT sampler even without NOP. SAC uses physical replay actions and requires distributions with pathwise/straight-through actor gradients; ordinary categorical SMB is for PPO, Gumbel SMB for SAC.
- PPO optimizer checkpoints include adaptive LR controller state and its enabled flag; restoring only Adam's learning rate can restart canceled warmup. Legacy checkpoints without controller metadata retain constructor defaults. The convenience trainer derives the controller's KL threshold from the resolved PPO `target_kl`.
- `as_benchmark_policy` sends only non-privileged fields to the actor and freezes normalization without changing training RMS. It owns recurrent/previous-action/distribution state, preserves each submodule's train/eval mode, and converts packed actions to the simulator dictionary. Create a fresh adapter per evaluation and use the same device as its policy. The actor is shared; do not train concurrently with evaluation.
- `swarmbots.record_policy` and `swarmbots.learn.record_checkpoint` use live exact-state episode recording, close their environments, and wait for MP4 writers. `swarmbots record`/`examples/record_policy.py` support checkpoints or custom `module:factory` callables. Checkpoint recording shares `training._make_policy_env` with the trainer to avoid allocating replay/optimizer state; callers must provide matching task/architecture/distribution/NOP settings. Unlike benchmark scoring, recordings recycle lanes to finish the requested video count.
- Public construction and evaluation live in `swarmbots/benchmark`. Evaluation accepts one episode per lane, preserves lane order, and rejects `num_episodes > num_envs`. Repeated early-finishing lanes must never displace slow lanes. Metadata serialization preserves distribution dataclass types and resolved settings.
- Protocol 0.1 permits centralized, partially centralized, and decentralized actors to combine non-privileged observations across agents within a world. Do not equate the privileged-observation boundary with a decentralized-execution requirement. The Gymnasium interface returns device-resident PyTorch tensors; NumPy-based wrappers require adaptation.
- Registry defaults share morphology pool seeds 42000–42049. Evaluation seeds change sampling, not pool membership. Protocol 0.1 does not claim held-out-morphology generalization.
- Environments use SAME_STEP autoreset. Terminal observations are in `final_obs`, selected by `_final_obs`; returned observations belong to reset episodes. Observation buffers may be reused. Indexed reset writes must assign back to their source tensor: integer-indexed selections are copies, not views.
- Explicit, partial, and automatic resets share `_reset_worlds` and use CPU-settled snapshots whenever `reset_settle_time > 0`. Seeded resets clear prefetched snapshots before reseeding. The one-shot `settle_initial_reset` API was removed; disable settling for custom variants with `reset_settle_time=0`. Protocol 0.1 uses settled first episodes; scores from the earlier unsettled-first-episode behavior need rerunning. The task matrix tests default settling; lifecycle tests cover staggered episodes with the async buffer and CUDA's full 500-step limit.
- CI is reusable via `workflow_call`; release builds depend on it. CPU jobs install the EGL dispatch library and Mesa runtime (`libegl1`, `libegl-mesa0`, `libgl1-mesa-dri`) and set `MUJOCO_GL=egl` for tests and installed-wheel checks. Missing EGL causes a MuJoCo import error; switching to OSMesa instead caused a native crash while importing Triton in both Python jobs. Installed-wheel checks must execute outside the checkout. CPU CI skips CUDA tests; explicitly verify CUDA availability and run `python -m pytest -m cuda` before releases. Public documentation is user-facing; keep contributor and publishing procedures out of the README and `docs/`.
- Warp graph capture must use `data.qpos.device`; MuJoCo Warp's Model has no qpos field. This path is CUDA-only and is invisible to CPU integration tests.
- Different task observation shapes share Dynamo's function cache. A full 14-task sweep can exhaust its specialization limit. GPU tests reset compiler state between cases; use one process per task/configuration or explicitly reset compiler state after closing the previous environment. Do not silently reset callers' compiled policy state inside the environment.
- Use `.venv/Scripts/python.exe` on Windows. In the managed Windows sandbox, redirect TEMP/TMP and TORCHINDUCTOR_CACHE_DIR into pre-created `.tmp` directories. Python 3.13 creates temporary directories with restrictive 0o700 ACLs that exclude the sandbox identity. For sandbox-only validation, a `.tmp` sitecustomize.py can wrap os.mkdir to replace 0o700 with 0o777 on Windows; set PYTHONPATH to that directory for subprocess builds too. Never ship that workaround in the package.
- For sandboxed CLI runs outside pytest, also set `WARP_CACHE_PATH` to a writable `.tmp` directory; otherwise Warp compilation fails with `PermissionError` in the default AppData cache. The pytest fixture already redirects its own Warp cache.

## Release procedure

Keep this procedure in agent/contributor notes. The publication trigger is a pushed version tag, as defined in `.github/workflows/release.yml`; creating a GitHub Release is not required. The workflow runs the reusable CI suite, verifies the tag matches the package version, builds with `uv build --no-sources`, checks distribution metadata with Twine, generates attestations, and publishes through the PyPI trusted publisher using the `pypi` GitHub environment.

1. Choose a new, unused package version. Preserve the alpha designation while the benchmark remains alpha. The example below uses `0.1.0a3`; replace it with the intended version for later releases. Run commands from the repository root in PowerShell and stop if any command fails.

   ```powershell
   $releaseVersion = '0.1.0a3'
   uv version $releaseVersion --no-sync
   ```

   `uv version` updates `pyproject.toml` and re-locks `uv.lock`; `--no-sync` postpones the environment update until validation.

2. Set `CITATION.cff`'s `version` to the same value, update the pinned installation example in `README.md`, and add a dated `## <version> - YYYY-MM-DD` section at the top of `CHANGELOG.md` describing the release. Preserve older changelog entries. `tests/test_release_metadata.py` checks consistency between the package version, citation metadata, and changelog.

3. Validate the release metadata and CUDA path before publishing. CPU CI also runs lint, the full test suite, and installed-wheel checks on Linux with Python 3.11 and 3.13. Installed-wheel checks run outside the checkout. Use the sandbox/cache workarounds above only when validation runs in the managed Windows sandbox.

   ```powershell
   uv sync --locked --extra dev
   .venv\Scripts\python.exe -m pytest tests/test_release_metadata.py
   .venv\Scripts\python.exe -c "import torch; assert torch.cuda.is_available(), 'CUDA is unavailable for release validation'"
   .venv\Scripts\python.exe -m pytest -m cuda
   git diff --check
   ```

4. Stage the intended release files and review the staged diff before committing. The following covers metadata, agent notes, and documentation; explicitly stage any additional source or test changes intended for the release. Include new files, such as bibliography entries, rather than relying only on staging tracked changes.

   ```powershell
   git add pyproject.toml uv.lock CITATION.cff CHANGELOG.md README.md MANIFEST.in AGENT_NOTES.md docs references.bib
   git diff --cached
   git commit -m "Release $releaseVersion"
   ```

5. After successful validation and review, push the release commit to `main`, create an annotated tag, and push that specific tag. The tag must be exactly `v` followed by the package version. **Pushing the tag starts PyPI publication after CI passes.**

   ```powershell
   git push origin main
   git tag -a "v$releaseVersion" -m "SwarmBots $releaseVersion"
   git push origin "v$releaseVersion"
   ```

6. Monitor the [release workflow](https://github.com/brn-dev/swarm-bots/actions/workflows/release.yml) until the publish job succeeds, then verify the version on [PyPI](https://pypi.org/project/swarmbots/). A successful tag push alone does not confirm publication. If a released version needs a correction, prepare a new version instead of overwriting its tag or uploaded distributions.
