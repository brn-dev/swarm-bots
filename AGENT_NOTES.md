# Agent Notes

Keep only durable architecture notes and gotchas. Delete stale detail instead of preserving trivia.

## Map

- `swarmbots/mj_env` is the CPU MuJoCo path; `swarmbots/mjw_env` is the MJWarp batched GPU path; `swarmbots/learn` contains PPO/MAT/RMAT, rollout, replay, wrappers, action dists, checkpointing, logging, and world-model wrappers.
- Scripts under `scripts/` are examples/entrypoints. Shared modern MJW experiment setup is in `experiments/mjw_experiment_common.py`; old experiment variants are not automatically canonical.
- See .ref for reference code of xLSTM, Multi-Agent Transformer and Stable Baselines 3.

## SAME_STEP And Wrappers

- Vector envs and learn wrappers assume `gymnasium.vector.AutoresetMode.SAME_STEP`; read `gymnasium_autoreset.md` before touching reset/rollout code.
- On done steps the returned obs is already reset obs. Terminal obs is `infos["final_obs"]` with `infos["_final_obs"]`; terminal stats may be in `infos["final_info"]`.
- Obs wrappers must transform `final_obs` like normal obs, but obs norm must not update RMS from `final_obs`.
- Standard learn wrapper order: `SwarmBotsLearnEnvWrapper -> optional TorchShuffleAgentsWrapper -> TorchRecordEpisodeStatisticsWrapper -> TorchProgressGuidanceEpisodeStatsWrapper -> TorchFeatureWiseObsNormWrapper(s) -> optional TorchTransitionObsWrapper -> TorchNormalizeRewardWrapper`, skipping reward norm when PopArt owns it.
- `SwarmBotsLearnEnvWrapper` owns numpy/torch conversion and `env.action_backend`. Learn obs require `local_obs`, `global_obs`, `hidden_local_vars`, `hidden_global_vars`; `agent_mask` is optional.
- Observation layout changes must update `build_obs_indices(...)` and related global-scalar target logic. Normalization and world-model targets depend on those indices.
- Done `final_obs` in `TorchShuffleAgentsWrapper` uses the old permutation; returned reset obs gets the new one. `TorchTransitionObsWrapper` keeps terminal transition features in `final_obs` but zeros reset obs.
- Env obs buffers are not durable; async/shared-memory/GPU envs and `copy=False` conversions can mutate them after the next env call.

## Rollout And Replay

- `collect_steps()` chunks can start mid-episode. Use `PPOEpisodeSegment.is_true_episode_start`; do not infer from chunk position.
- Recurrent state is explicit in `PPORolloutState`. SAME_STEP terminal bootstrapping evaluates `final_obs` without committing the resulting recurrent state; reset obs consumes the done mask on the next rollout step.
- Flat PPO configs use `PPORolloutBatch`; recurrent MAT/RMAT uses env-major TBPTT rows with one initial recurrent state per row, not per-step stored recurrent state.
- Off-policy rollout/replay lives in `swarmbots.learn.algos.off_policy`. `OffPolicyReplayBuffer` is a per-env ring stream with `capacity + 1` obs slots; terminal `final_obs` is sparse by transition slot while returned reset obs stays in the stream.
- Replay-buffer multi-op gather/window/segment/candidate-mask and temporal-checkpoint bookkeeping is isolated in `replay_buffer_tensor_ops.py`; those operations compile automatically for CUDA replay storage and stay eager for CPU storage. Single ring-index remainder kernels intentionally stay eager because they offer no fusion opportunity. `replay_compile_tensor_operations` can override compilation through SAC/RecurrentSAC.
- Off-policy recurrent replay stores optional temporal-state checkpoints on observation slots via `temporal_state_store_interval`, backed by a compact checkpoint pool sized to the maximum simultaneously retained checkpoints rather than a dense state tensor for every observation slot. `sample_episode_segments(...)` remains episode-contained by default for ordinary multi-step NOP, but `allow_episode_boundaries=True` samples fixed replay streams for recurrent SAC from checkpoint-backed starts. Recurrence resets from `episode_start_mask`, truncated `final_obs` bootstraps branch from the pre-reset actor state, and recurrent NOP masks every target after the first done in each origin window. `sample_episode_windows(...)` instead samples ordinary replay origins uniformly and attaches padded, time-masked future windows without crossing episode boundaries.
- During random off-policy collection, pass a recurrent policy so its temporal state advances while its actions are discarded. Introducing a recurrent policy mid-episode without tracked state is rejected.
- Keep collecting into a nonempty replay buffer with the returned `OffPolicyRolloutState`; resetting the env into that buffer without state breaks observation-slot continuity.
- `OffPolicyReplayBatch` has no `next_previous_actions`; use sampled `actions` when conditioning on `next_*` obs. Replay batches and `OffPolicyReplayBuffer` store physical environment actions. Pass `rollout_device` explicitly when moving env, policy inference, and resumed rollout state.
- gSDE off-policy rollouts need `gsde_reset_mode`; `OffPolicyRolloutState.gsde_noise_state` preserves the standard-normal rollout noise across SAC training, so interval/probability reset cadence survives replay-batch sampling.
- Use `resolve_gsde_reset_mode(...)` for shared gSDE reset-mode requirements and range validation across PPO, SAC, rollout, and recording paths.
- SAC lives in `swarmbots.learn.algos.sac` and reuses off-policy rollout/replay. It intentionally rejects non-`Box` action sub-spaces; use continuous connector actions for TMASAC/SAC, not Bernoulli connectors.
- `SAC(rollout_warmup_steps_per_env=...)` mirrors PPO steady-state rollout warmup: it advances env/rollout state without replay writes or training counters, then the first real collection writes from that returned `OffPolicyRolloutState`.
- `SAC(learning_rate_warmup_updates=...)` warms actor/critic optimizer LRs only. `ent_coef_learning_rate=None` follows the main LR, while an explicit entropy-coefficient LR stays independent; the common TMASAC experiment runner uses `1e-3` for faster alpha adaptation. On CUDA, SAC's stable tensor-only loss/target/masking regions and optimizer steps compile by default; actor/critic optimizer steps stay eager during LR warmup to avoid recompiling on every changed LR. Compiled forwards get compiled backward graphs through AOTAutograd. SAC NOP compiles one end-to-end prediction-loss graph rather than separately wrapping its nested modules.
- SAC checkpoints intentionally omit replay and rollout state. Loading SAC clears both and waits until the new replay contains `max(learning_starts, batch_size)` transitions before updating again; restored global counters and optimizer schedules continue, so mature checkpoints fill replay with policy actions rather than restarting the original random-action phase. The default replay capacity is a fixed total budget divided across envs; explicit `buffer_capacity_per_env` values still scale per env. Any explicit capacity must leave total replay capacity at least as large as that fill target; the common MJW runner expands its per-env capacity when needed.
- SAC accepts `auto_<value>` and `auto*<value>` for entropy coefficient/target suffixes. Actor, Bellman, and learned-temperature entropy terms use log-probabilities averaged over active agents; automatic and explicit `target_entropy` values are per-agent targets. Current MJW TMASAC defaults use `ent_coef="auto_0.05"` and `target_entropy="auto_0.5"`; loading an old summed-agent SAC checkpoint resets alpha from the current configuration while retaining the compatible actor/critic optimizer state.
- SAC actor updates include action-dist extra losses through the loss-only path when available; per-agent extra-loss tensors are summed per replay row independently of SAC's mean-agent log-probability entropy reduction. Continuous action distributions no longer expose an action-magnitude auxiliary loss or runtime coefficient. The shared MJW TMASAC setup sets continuous-action `ent_loss_coef=0`, so SAC's learned temperature is its only entropy regularizer; sign-magnitude distributions then skip entropy-loss and entropy-metric computation entirely. PPO keeps its `1e-3` action-distribution entropy loss. `EntropyLossConfig.max_entropy` is deprecated alias for `entropy_floor`.
- Recurrent TMASAC is isolated in `recurrent_tmasac_policy.py` and `recurrent_sac.py`; plain `SAC` rejects policies that require recurrent training. Its actor uses `RMATEncoderConfig`, so LSTM/sLSTM/mLSTM selection follows the existing R-MAT temporal-model class/config fields. The critic remains ordinary action-conditioned MAT by default (`recurrent_critic=False`) and keeps an ordinary `MATEncoderConfig`; optional recurrent critics require an `RMATEncoderConfig`, reconstruct state from zero during burn-in, and are not advanced during rollout. `RecurrentSAC` defaults to 32 burn-in + 64 learning steps and a 32-step actor-state checkpoint interval; the checkpoint interval cannot exceed the learning sequence length because checkpoint-anchored sampling would otherwise leave replay transitions untrained. It only supports shared/non-independent NOP sampling and processes every valid aligned NOP origin in parallel without a second replay sample or history reconstruction. Overlapping NOP action/target windows stay as `unfold` views with separate batch/origin dimensions until the existing recurrent world-model adapter flattens them for the model call. `SegmentTMASACPolicy` is an experimental feed-forward MAT adapter for `RecurrentSAC`: it flattens segment/time for policy calls, stores a one-scalar dummy checkpoint so candidate starts match recurrent sampling, and skips actor burn-in computation while retaining burn-in in replay-window selection. Ordinary `SAC`/`TMASACPolicy` still allocate no temporal replay storage.
- `RecurrentTMASACPolicyConfig.actor_state_critic_input_config` optionally gives the feed-forward critic a detached representation of the actor's post-observation recurrent state. Only the last RMAT layer is used; its temporal model returns the dense post-step state sequence by stacking states once during recurrence, while the generic selected-state path remains sparse and handles only padded truncation indices. LSTM also selects its last internal layer and supplies `(h, c)`, while sLSTM supplies `(h, c/n, softsign(log(n)+m))` by default, treating the zero initial/inactive-agent normalizer as one so masked agents stay finite. A critic-owned MLP projects this before local-input concatenation, with separate online/target copies. This is intentionally incompatible with mLSTM and `recurrent_critic=True`; leaving the config as `None` preserves the original model and state dict.
- TMASAC SAC actors accept continuous configs whose action-dist registry declares pathwise or straight-through actor gradients. Gumbel sign-magnitude is explicitly straight-through: it uses a hard sign in forward and a biased soft relaxation in backward, while PPO uses exact categorical sampling/likelihoods. SAC with `GSDEConfig` requires an explicit `gsde_reset_mode`.
- `experiments/mjw_experiment_common.py` supports feed-forward `policy_variant="tmasac"`, actor-recurrent `policy_variant="r_tmasac"`, and feed-forward MAT with recurrent segment sampling via `policy_variant="segment_tmasac"`; the latter two select `RecurrentSAC`, while only `r_tmasac` exposes actor-only RMAT width/MLP-layout. Recurrent TMASAC compiles strict full-graph, static-shape actor entry points spanning RMAT encoding, the actor head, compile-friendly action sampling/log-probabilities, and masking for configured rollout and learning sequence lengths; burn-in uses an encoder-only full graph. Compiled mode rejects other lengths instead of silently falling back. Feed-forward TMASAC likewise compiles its complete actor as one full graph for compile-friendly action distributions when it does not share an observation encoder; shared-encoder and segment-training paths compile the actor action-generation tail separately, including QCX's autoregressive loop. PyTorch `nn.LSTM` actor encoders stay eager by default because Dynamo RNN support is experimental, but their actor head plus compile-friendly action distribution still compile together; `rmat_experimental_compile_lstm=True` explicitly opts the complete actor into compilation. The learning RMAT forward returns fixed-capacity padded post-step states only for truncation indices (`max_truncations_per_segment`, default one per sampled row); ordinary target actions reuse shifted actor outputs and one T1 pass handles the final and truncated successor observations. Feed-forward critic/target and NOP are also compiled. sLSTM can compile its eager recurrent step when the outer actor is not compiled. TMASAC NOP is configured with `SACNOPConfig`, not `NextObsPredWrapper`. `SACNOPConfig` defaults to disabled; enable it only with explicit next-observation prediction targets.
- Action distributions follow the PyTorch naming convention: `sample()` is ordinary non-reparameterized sampling, `rsample()` keeps the actor-gradient path. `ActionDist.get_actions_with_log_probs(..., use_rsample=True)` is for SAC actor updates; rollout and target-Q sampling use the default ordinary `sample()` path.
- Continuous action distribution construction and actor-gradient capabilities are registered together in `hybrid_action_dist.py`; add new config types to that registry instead of extending policy-specific type tuples.
- gSDE stores standard-normal temporal noise and multiplies it by the current live std during sampling. This keeps PPO/MAT sampling consistent with likelihood evaluation after optimizer updates and lets SAC's critic-through-action gradient reach `log_stds`; do not cache already-scaled exploration matrices.
- `TMASACPolicy` uses separate actor/critic MAT encoders by default. Its twin Q networks share the expensive action-conditioned encoder by default; `TMASACCriticConfig.independent_encoders=True` opts into separate representations. Independent critic latents stay separate for Q1/Q2 and are concatenated for critic NOP, so that NOP source has width `2 * d_model`. The default critic jointly coembeds raw observation/state inputs and actions exactly as before; `TMASACCriticConfig.separate_observation_action_encoders=True` instead projects observation/state inputs to `d_model` and actions to `action_encoder_dim` before the existing fusion MLP, and also applies to explicit recurrent critics. `action_encoder_dim=None` resolves to `max(1, d_model // 2)`; `mjw_experiment_common.run_experiment(...)` exposes the feature as `tmasac_separate_observation_action_encoders`. Optional shared observation encoding is policy-owned via `shared_encoder_config` (or legacy `share_observation_encoder=True`); actor reads detach shared latents, while critic/NOP critic gradients update the shared encoder and its target copy is Polyak-updated with the critic target. Target critics and the target shared encoder stay in eval mode while the online policy trains, so configured dropout does not randomize Bellman targets. The critic coembeds local obs/shared latents, hidden local vars, and actions per agent; public and hidden global inputs are embedded into every token before its transformer rather than appended at the value head. SAC NOP modules are selected by latent source (`critic`, `actor`, `both`, or `shared_encoder`); `both` means separate actor/critic projections, transition models, and losses. Action-conditioned critic NOP skips the first transition by default because its source latent already consumed the first action; `skip_first_transition_for_critic=False` restores the old behavior, while actor/shared-encoder NOP always transitions on the first action. `SACNOPConfig.num_next_steps` counts predicted next observations and their actions; with critic skipping enabled, the encoder consumes the first action and the transition model consumes only the remaining actions. An unspecified SAC NOP latent projection resolves to one adaptive-width hidden layer, while the common TMASAC experiment setup uses two `source_latent_dim` hidden layers. SAC defaults to shared-origin NOP sampling (`independent_nop_sampling=False`): ordinary Bellman origins get PPO-style padded future windows, and critic NOP reuses the Bellman forward latents for every horizon. `independent_nop_sampling=True` restores a separate NOP replay batch; multi-step independent sampling requires full contiguous segments and may skip only the auxiliary loss when none exist, while one-step independent sampling uses a separate ordinary replay batch. A distinct `nop_batch_size` is only valid for independent sampling.
- TMASAC actor ablations are selected with `TMASACActorHeadConfig.kind`: `independent` is the original MAT encoder plus per-agent action distributions, `qcx` samples agents autoregressively with the shared QCX decoder conditioned on earlier sampled actions, and `decentralized` removes inter-agent attention from the actor encoder while retaining its token encoders, transformer feed-forward blocks, residuals, and normalizations. The critic is unaffected. A decentralized actor rejects shared observation encoding because that would reintroduce critic-owned agent mixing. The same modes work for feed-forward, segment, and recurrent TMASAC; `run_experiment(...)` exposes them as `tmasac_actor_head_kind`. Actor heads own their action-generation strategy through `actions_and_log_probs(...)`; the policy passes its action distribution into that interface and must not branch on concrete head types during sampling.

## Policies And Action Dists

- `MATQCBasePolicy` holds shared QCS/QCX/QCC PPO plumbing. QCS is the main transformer policy; QCC subclasses QCS with its own decoder; QCX is query-to-context only; `MATDecPolicy` is decoderless despite the name.
- `MATEncoder` owns its custom `MATEncoderLayer` stack directly. Its transformer and local/global observation feed-forwards accept `MLPConfig` or the standard GLU-family configs; RMAT uses the transformer config for both its main and optional inter-module blocks. GLU configs build one concrete variant unless they contain `GLUStackConfig`; stacked GLUs project every complete gated block back to the site output width and can independently enable per-block pre-normalization and residuals around width-preserving blocks. `norm_first_layer=False` and `residual_first_layer=False` independently disable those operations only for the first GLU, for sites such as pre-normalized transformer blocks with an outer residual. `transformer_ff_config=None` preserves the PyTorch-style one-hidden-layer default using `dim_feedforward`; local/global observation configs default to direct linear projections. `transformer_ff_init_gain=None` intentionally preserves cloned identical MAT layer initialization.
- `MATOrigPolicy` requires contiguous true-prefix `agent_mask` and shifted previous-agent actions; inactive-agent log-probs must be zeroed in rollout and `evaluate_actions()`.
- QCS/QCC/QCX support arbitrary inactive positions if each row has at least one active agent. `assume_agent_mask_is_active_prefix=True` selects the cheaper prefix path.
- RMAT variants share `RMATPolicyMixin` and `RPPOWMSampler` env-major TBPTT rows. `RMATEncoder` owns its custom `RMATEncoderLayer` stack directly; `transformer_ff_config` also applies to the optional inter-module feed-forward. Temporal cores must honor reset masks. The default LSTM temporal core/output projection are biasless so reset zero-input rows do not emit learned initial-state priors; `RMATEncoderConfig.use_temporal_output_projection=False` removes the extra temporal output projection.
- Recurrent-state resets must overwrite reset rows rather than multiply them by zero; multiplication does not clear NaN/Inf state values.
- xLSTM reference projection defaults are structured: sLSTM input-to-gate projection is split by memory head, while mLSTM Q/K/V projection is split into `qkv_proj_blocksize` feature blocks independently of its memory heads. `dense_input_proj=True` and `dense_qkv_proj=True` restore the respective old dense projection layouts. Reference small initialization uses the full temporal-model width, and both cells use zero-initialized residual output-norm weights whose effective scale is `1 + weight`.
- For MAT customization, override `_build_encoder*()` and `_build_action_dist(...)`; do not mutate inherited fields after `super().__init__()`.
- `ActionDist` action nets are always `nn.Linear`, even when `latent_dim == action_dim`, so `action_net_init_gain` is honored instead of accidentally passing logits/means through unchanged.
- Sign-magnitude distributions share `SignMagnitudeActionDist`, which owns exact categorical sign selection plus common density and entropy logic. Beta/Kumaraswamy family classes own magnitude-specific math, while inverse-CDF mixture, Gumbel, and sticky behavior stays in leaf classes. Gumbel Kumaraswamy must not inherit the inverse-CDF reparameterized variant.
- Deterministic sign-magnitude actions use the highest-density signed component mode, not the mixture expectation; this keeps deterministic evaluation on the distribution support modes instead of potentially producing a low-density near-zero action.
- `ActionDist.compile_friendly` controls torch.compile coverage. Mutable action-dist scalars must be tensors/buffers, and sticky dists must keep `requires_previous_actions()` structurally stable even when annealed to zero.

## World Models

- World models are policy wrappers: `NextObsPredWrapper` and `SPRWrapper`. They must delegate sampler selection, temporal-state APIs, and `after_optimizer_step()` to the wrapped policy; flat WM samplers break RMAT.
- WM losses use `wm_actions`, not PPO current-step `actions`; recurrent padding uses `time_mask` via `wm_recurrent_batch.py`.
- NOP global-observation prediction needs explicit global scalar/rot6d target indices and pools predicted agent latents across active agents before global heads. `SPRWrapper` currently rejects RMAT; use `NextObsPredWrapper`.
- Global NOP predictions pool with the effective next-state loss mask (the current/next mask intersection) and exclude rows with no valid next-active agents from global losses.

## Scenarios And MJW

- `SwarmBotsEnv` delegates cadence, reset baselines, and progress deltas to scenarios. Do not add env-level `action_repeat` or generic `BaseScenario.compute_progress(...)`.
- Scenario `global_obs` layouts are contracts; changing them requires learn obs-index and WM target updates. `SwarmBotsEnv.reset(seed=...)` must reseed `scenario.rng`.
- `MultiScenarioVectorEnv` combines fixed lane groups from multiple homogeneous SAME_STEP vector envs. It requires identical local-observation, agent-mask, and action spaces; pads `global_obs`, `hidden_local_vars`, and `hidden_global_vars`; and adds an explicit integer `scenario_id` to normal and terminal observations. Partial resets normalize masks to NumPy, skip child groups whose sliced mask is all false, and reuse their latest observations because Gymnasium `SyncVectorEnv` requires NumPy masks and rejects all-false masks. Explicit seed lists are rejected before any child resets when a child advertises `supports_per_env_reset_seeds=False`; MJW does so because it owns one batched RNG rather than independent lane RNGs. When every child advertises deferred stepping, it begins every child before ending them; MJW uses a pinned asynchronous status readback so later scenario GPU work is submitted before earlier host-side terminal/reset handling. The off-policy replay buffer stores the scenario ID on observation slots, including separate terminal rows. Gymnasium vector wrappers do not forward arbitrary attributes, so learn wrappers explicitly preserve `scenario_names` and `scenario_observation_dims` for policy validation.
- TMASAC optionally owns scenario-banked linear/MLP adapters through `TMASACPolicyConfig.scenario_encoder_config`. A scenario with a zero-width global, hidden-local, or hidden-global field bypasses that field's encoder and learns an output-sized vector instead; zero-width scenarios do not own normalization or MLP parameters. Actor and critic adapters are separate, the critic target has its own Polyak-updated frozen copy, and a learned scenario embedding is appended to encoded public-global observations. Feed-forward, recurrent, and segment TMASAC support the adapters; shared observation encoding and global NOP targets remain unsupported. Recurrent adapters run before RMAT, and recurrent replay preserves scenario IDs through burn-in slices, flattened batches, and successor/truncation branches. When the feature is disabled, the old module/state-dict and metric schemas remain unchanged.
- Episode metrics retain their aggregate keys and additionally use `scenario/<scenario_name>/...` for reward, length, time, reward components, success rate, and completed-episode count whenever rollout infos provide scenario metadata.
- Render overlays are visual only via `BaseScenario.add_render_geoms(scene)` after `Renderer.update_scene()`; do not use them for physics/model geometry.
- `MJWSwarmBotsVectorEnv` is a real `gymnasium.vector.VectorEnv` with one MJWarp model, batched GPU `Data`, and `action_backend="torch"`.
- Scenario-specific MJW logic belongs in scenario runtime classes. Runtime metadata flows through `scenario.build_runtime_metadata(...)`; keep `MJWModelMetadata` generic. Terminations flow through `MJWStepResult.terminations`.
- MJW reset modes: direct, one-shot `settle_initial_reset`, and background CPU-settled snapshot buffer. Done-world resets consume ready snapshots and block only on buffer misses.
- MJW fixed-shape observation building, action preprocessing, and unstable-observation masking live in `mjw_env_tensor_ops.py`. They compile as strict static full graphs by default on CUDA and stay eager on CPU; `compile_tensor_operations` and `tensor_operations_compile_mode` override this on `MJWSwarmBotsVectorEnv` and the shared experiment runner. Keep Warp launches and variable-cardinality connector bookkeeping outside these graphs.
- MJW treats every non-finite `qpos`/`qvel` value as simulation instability, terminates that world, masks its terminal observation, resets it, and sends one Discord warning per run. Instability notification data transfers with the existing done/reset synchronization; keep error-observation masking entirely on-device rather than using CUDA `nonzero()`.
- Keep MJW step hot paths kernelized and allocation-light: connector matching is in `mjw_kernels.py`, Warp indices stay `int32` unless PyTorch indexing forces `int64`, and GPU scratch buffers should be reused.
- Live MJW recording uses one shared `mujoco.Renderer`; `max_parallel_episodes` caps concurrency, not renderer count. Resolutions above 640x480 need `ensure_mujoco_offscreen_framebuffer(...)` before renderer construction.
- Vertical reach is not climb: the green goal box is visual/non-colliding, success is any active unit entering it, and main shaping is max active-unit height inside the front-wall reach column.

## Runtime

- Put all agent-created temporary files and test directories under the repository-root `.tmp/`; do not create ad hoc temporary folders at the repository root. `.tmp/` is Git-ignored.
- Runtime hyperparameters are live attributes; mutating config dataclasses after init does nothing.
- `as_device(...)` canonicalizes bare CUDA requests to the current indexed CUDA device. Keep device values canonical: PyTorch considers `cuda` and `cuda:0` unequal, which can trigger redundant transfers or optimizer replacement.
- `BaseAlgorithm.learn(logging_buffer_size=...)` aggregates sampled log dictionaries before console/CSV/W&B output; `log_interval` still controls which iterations are sampled. Plain metric values use the last value, explicit buffered reductions handle mean/std, sums, and rates, and `SummaryStatistics` combine by sample count. Full buffers are swapped into a bounded queue and aggregated/persisted by one background `MetricsLogger` thread; `flush()` and `close()` drain it and surface worker failures. Bounded action histograms use fixed edges (continuous `[-1, 1]`, Bernoulli `[0, 1]`) and therefore combine exactly; histograms with dynamic/differing edges, such as rewards and standard deviations, are rebinned approximately because raw samples are unavailable.
- MJW first-episode staggering must produce positive lengths. A zero limit still truncates after the first step, so it collapses into the one-step bucket instead of representing a distinct zero-step episode.
- `experiments/mjw_experiment_common.run_experiment` defaults new MJW experiments to continuous connector actions via scenario kwargs; existing experiment wrappers that should preserve binary connectors set `continuous_connector_actions=False` explicitly. It also exposes MAT policy `enc_nhead`/`dec_nhead`, typed `mat_encoder_transformer_ff_config`/`rmat_actor_transformer_ff_config`, and binary connector `bernoulli_initial_prob` for experiment sweeps. MatDec only uses encoder heads; MatQCX uses both encoder and decoder heads. The NOP transition model head count stays on the runner default unless that path is changed separately.
- The PO-wall medium continuous-connector TMASAC experiment is split into `experiments/mjw_po_wall_medium_1024x1_tmasac` and intentionally uses `num_envs=1024`, `rollout_steps_per_env=1` so SAC trains after each single env step batch. Keep it separate from the PPO/MAT `1024x4` continuous-connector experiment.
- `experiments/mjw_po_wall_medium_1024x1_ract_tmasac` compares width-256 LSTM, sLSTM, and stacked sLSTM→mLSTM recurrent actors across small-end, big-end, and two-small RMAT MLP layouts. It uses fp16 temporal checkpoints every 16 steps and a 1024-step per-env replay ring matching the feed-forward SAC replay horizon; compact checkpoint pooling retains 65 checkpoints per env. Recurrent batches contain 16 sequences with 32 burn-in + 64 learning steps, so each update trains on `16 * 64 = 1024` transitions like the feed-forward SAC batch, while burn-in is context-only.
- Activation factories with `ParameterLearnMode.PER_FEATURE` need explicit feature counts; generic activation paths should use `make_activation(...)`.
- Initialization gains: hidden/projection/transformer-FF `1.0`; output/action/value/prediction heads `0.01`. MJW `PredictedStdConfig` also initializes its predicted log-std head with the action-head gain so `base_std` is the actual initial anchor instead of being swamped by actor latents.
- Target Python is `3.13`; use `uv` because plain `pip install .` misses PyTorch CUDA package sources.
- Run tests through uv, e.g. `uv run python -m pytest tests/test_off_policy_replay.py`. In Codex desktop `cmd.exe`, `.venv\Scripts\python.exe` can fail with `Access is denied` because it is a uv-managed launcher; do not treat that as a repo failure.
- Headless Linux defaults `MUJOCO_GL=egl` for `swarmbots.mj_env` and `swarmbots.mjw_env` when unset.
